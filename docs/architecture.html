Policy Assistant

A private AI assistant that answers employee questions from our company policy PDFs. Every answer cites the policy section and page it comes from, runs through safety checks, and is recorded in an audit trail. Every component runs on our own infrastructure.

100% local, open sourceNo policy text or question leaves our network
Two separate pipelinesIngestion (admins) and retrieval (employees)
Guardrails on both sidesChecks the question and verifies the answer
Fully auditableEvery login, upload and question is traced

System at a glance

Employees and admins use one web app. What each person sees depends on their role. All requests pass through a single API that checks identity, routes the work to the right pipeline, and records what happened. The AI models and data stores sit behind the API and never face users directly.

What happens when an employee asks a question

Nine steps run in order and each one is timed and recorded. Where a step can fail, there is a planned fallback, shown below the main row. The employee always gets a clear message instead of an error screen or an invented answer.

How a policy PDF becomes searchable

When an admin uploads a PDF, a background job processes it: the admin gets an immediate response and can watch the job's status. The chunking follows the policy's own structure (sections, sub-sections, tables), so answers can point to the exact section and page.

Controls leadership should know about

Access

  • Sign-in with user ID and password (hashed with bcrypt)
  • Two roles. Employees cannot upload policies; the server enforces this, not just the screen.
  • An account locks for 15 minutes after 5 failed attempts
  • Sessions expire after 60 minutes, and logging out revokes them on the server

Answer quality

  • Answers come only from policy text and cite the section and page
  • The relevance gate refuses when nothing in the policy matches
  • Answers not supported by the policy text are withheld
  • Numbers that don't appear in the policy are flagged to the user

Data protection

  • All models run locally, so no data goes to external AI providers
  • Personal data in questions is masked before processing
  • High-risk identifiers are redacted from answers
  • Prompt-injection attempts are blocked and logged

Accountability

  • Every login, upload, question, block and feedback is in the audit trail
  • Every answer links to a trace ID with timings for each step
  • The model and prompt version are stored with every answer
  • Admins can export the audit trail and login history as CSV

How accuracy is measured

A golden set of questions with known answers runs through the full pipeline. A local AI judge scores the results with DeepEval, and each report records the exact model, prompt version and settings, so scores can be compared across releases.

Finding the right text

Contextual precision, recall and relevancy (DeepEval). Hit rate and MRR against expected keywords.

Answering correctly

Faithfulness, answer relevancy and hallucination (DeepEval). G-Eval correctness against the reference answer.

Behaving as instructed

Prompt alignment with the prompt's own rules, plus citation quality, tone, bias and toxicity. Refusal accuracy on questions the policies don't cover. Guardrail accuracy.

In production

The AI grades every live answer in the background on five criteria. Employee thumbs up/down and guardrail blocks show on the admin dashboard.

Path to enterprise scale

Each of these can be swapped on its own, because the code keeps each component behind its own module.

  • Single sign-onReplace local passwords with Azure AD / Okta. The login-session and audit tables stay as they are.
  • PostgresMove app data from SQLite with a one-line change to the database URL
  • GPU LLM servingMove from Ollama to vLLM on a GPU node for more concurrent users
  • Qdrant clusterReplicated vector storage once the number of policies and users grows
  • Evaluation in CIBlock releases when faithfulness or correctness fall below a threshold (--fail-under is already built in)
